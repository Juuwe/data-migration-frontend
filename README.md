# data-migration-frontend

Фронтенд сервиса методов миграции данных на React + TypeScript. Бэкенд: [data-migration-backend](https://github.com/Juuwe/data-migration-backend).

## Стек

- React, TypeScript, Vite;
- React Router;
- React-Bootstrap, Bootstrap Icons;
- Redux Toolkit, React Redux;
- axios, swagger-typescript-api;
- vite-plugin-pwa (Workbox).

## Запуск

Требуется Node.js 20.19+ или 22.12+ (Vite 8).

```bash
npm install
npm run dev
```

Приложение откроется на <http://localhost:3000>. Сборка: `npm run build`, проверка линтером: `npm run lint`, предпросмотр production-сборки: `npm run preview`.

Для работы с бэкендом поднимите инфраструктуру из репозитория `data-migration-backend`:

```bash
docker compose up -d
```

Веб-сервис будет доступен на `http://localhost:8081`, MinIO — на `http://localhost:9010`. Тестовые пользователи из `migrations/init.sql`: `student@example.com`, `analyst@example.com`, `engineer@example.com`, `architect@example.com`, `reviewer@example.com`, пароль `password123`.

### Проксирование

В `vite.config.ts` настроены два маршрута, которые решают проблему CORS:

- `/api` → `http://localhost:8081` — запросы к веб-сервису;
- `/s3` → `http://localhost:9010` — объекты MinIO, префикс `/s3` отбрасывается.

Ссылки на MinIO, которые возвращает API, приводятся к виду `/s3/{bucket}/{key}` в `src/modules/media.ts`.

Адреса прокси можно переопределить переменными `API_PROXY_TARGET` и `S3_PROXY_TARGET`, например для отдельного стенда:

```bash
API_PROXY_TARGET=http://127.0.0.1:8082 \
S3_PROXY_TARGET=http://127.0.0.1:9011 \
VITE_MINIO_URL=http://localhost:9011 \
npm run dev
```

## Адаптивность

Вёрстка рассчитана на телефон и на широкий экран:

- на мобильном `.app-viewport` занимает `100dvh` без внешних отступов;
- от `700px` приложение ограничено шириной `1100px`, получает скруглённые углы и тень;
- плитка: 2 колонки на телефоне, 3 колонки от `700px`, 4 колонки от `1000px`;
- высота изображения карточки: `186px`, `210px` и `230px` на тех же breakpoint'ах;
- фильтр и нижнее меню растягиваются по ширине, но меню не шире `398px`;
- формы добавления и входа ограничены по ширине и центрируются.

Значения breakpoint'ов и колонок заданы в `src/pages/GridPage/GridPage.css`, размеры карточек — в `src/components/MethodCard/MethodCard.css`.

## PWA

Плагин `vite-plugin-pwa` генерирует `manifest.webmanifest` и service worker. В `vite.config.ts` заданы имя, иконки, `display: standalone`, цвет темы и precache оболочки приложения. Иконки лежат в `public/pwa-192x192.png` и `public/pwa-512x512.png`.

```bash
npm run build
npm run preview
```

После сборки приложение можно установить как PWA. В production-сборке service worker кэширует HTML, JS, CSS, шрифты и изображения; видео из MinIO в precache не входят.


## Нативное приложение Tauri и поиск по изображению

В проект добавлен Tauri 2.x-клиент для гостя: страницы «Плитка» и «Лента», без авторизации и редактирования. В Tauri-сборке скрываются пункты «Добавить» и «Вход», а API и MinIO запрашиваются напрямую по IP компьютера в локальной сети.

Перед сборкой укажите IP в `src/modules/tauriConfig.ts` или через переменные окружения:

```bash
cp .env.tauri.example .env.tauri.local
```

```env
VITE_TAURI_API_BASE=http://192.168.1.96:8081
VITE_TAURI_S3_BASE=http://192.168.1.96:9010
```

Для сборки нужны Rust, Cargo и системные зависимости Tauri. Затем:

```bash
npm install
npm run tauri build
```

Если `npm install` падает на postinstall `onnxruntime-node` или `sharp`, установите зависимости без нативных скриптов:

```bash
npm install --ignore-scripts
```

Для браузерной/WebView-сборки используется `onnxruntime-web`, нативный Node-бинарник не нужен.

`npm run tauri dev` запускает dev-режим, `npm run tauri build` — собранное приложение (не dev).

Порт, который использует собранное Tauri-приложение при обращении к API, можно увидеть через tcpdump:

```bash
sudo tcpdump -i any -n 'tcp port 8081'
```

В строке запроса к API найдите локальный source port — он динамический, его нужно указать на диаграмме развертывания. В последней проверке был получен порт `60531`.

На странице «Плитка» доступен поиск по изображению: CLIP-модель `Xenova/mobileclip_s0` через `@huggingface/transformers` считает эмбеддинги английских описаний услуг и загруженной картинки, после чего карточки сортируются по косинусной близости. Порог регулируется в диапазоне `0.4–0.9`, количество результатов — TopK от 1 до 20. Английские описания для seed-услуг находятся в `src/modules/searchDescriptions.ts`.

По умолчанию используется компактная `Xenova/mobileclip_s0`. Для более тяжёлой SigLIP-модели задайте `VITE_AI_MODEL_ID=Xenova/siglip-base-patch16-224` при сборке.

## HTTPS-прокси

Production-сборка раздаётся Node.js-сервером `server/https-proxy.mjs` по HTTPS. Он же проксирует `/api` на `http://127.0.0.1:8081` и `/s3` на `http://127.0.0.1:9010`, поэтому телефон в локальной сети обращается к бэкенду ноутбука через один HTTPS-адрес.

```bash
npm run build
npm run cert
npm run serve:https
```

Сервер запускается на `https://0.0.0.0:3443`. В консоли выводится IP-адрес ноутбука для телефона. Сертификат создаётся скриптом `scripts/generate-cert.mjs` через OpenSSL и включает `localhost`, `127.0.0.1` и все локальные IPv4-адреса в SAN. Сертификаты не коммитятся.

Порты и адреса можно переопределить переменными `HTTPS_PORT`, `HTTPS_HOST`, `API_TARGET`, `S3_TARGET`, `TLS_KEY`, `TLS_CERT`.

## GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` собирает приложение с `GITHUB_PAGES=true` и `VITE_STATIC_MODE=true` и публикует `dist` через GitHub Actions. Адрес: <https://juuwe.github.io/data-migration-frontend/>.

Перед первым запуском в настройках репозитория нужно выбрать `Settings → Pages → Build and deployment → Source: GitHub Actions`. После этого workflow запускается при push в `react-spa-pwa-deploy` или вручную через `workflow_dispatch`.

На GitHub Pages нет бэкенда и MinIO, поэтому:

- гость получает данные только из mock-коллекции;
- медиа MinIO заменяется локальными файлами по умолчанию;
- для клиентских маршрутов создаётся `dist/404.html`;
- `BrowserRouter` использует `basename` из `import.meta.env.BASE_URL`.

## Кодогенерация API

```bash
npm run generate-api
```

Скрипт `scripts/generate-api.mjs` берёт OpenAPI-схему из `http://localhost:8081/docs/swagger.yaml` и создаёт `src/api/Api.ts` с axios-клиентом. Другой адрес можно передать через переменную окружения:

```bash
API_SWAGGER_URL=http://localhost:8081/docs/swagger.yaml npm run generate-api
```

Экземпляр сгенерированного клиента находится в `src/api/index.ts`; он автоматически добавляет `Authorization: Bearer <JWT>` к запросам.

## Redux Toolkit

Хранилище описано в `src/store.ts`, слайсы — в `src/slices`:

- `methodsSlice` — фильтр по времени, список услуг, лента, лайки и удаление; запросы к домену услуг выполняются через `createAsyncThunk` и сгенерированный axios-клиент;
- `draftSlice` — черновик пользователя, создание и публикация услуги;
- `userSlice` — email, признак авторизации, загрузка и ошибки.

Redux DevTools подключается автоматически в режиме разработки. При выходе из аккаунта фильтр услуг сбрасывается к значениям по умолчанию.

Запросы авторизации и деавторизации выполняются напрямую через axios (`src/modules/authApi.ts`), без кодогенерации и thunk. JWT сохраняется в `localStorage` и cookie, поэтому после перезагрузки страницы Redux снова находится в состоянии гостя, а токен остаётся в браузере.

Во время первой загрузки страницы показываются skeleton-заглушки, а кнопки и поля блокируются до завершения запроса. Полученные списки и лента кэшируются в Redux и не перезапрашиваются при переключении вкладок.

## Страницы

Навигация снизу: «Лента», «Добавить», «Плитка», «Вход». После авторизации пункт «Вход» заменяется кнопкой «Выход».

### Лента — `/feed?id={id}&next=true`

Одна опубликованная услуга с видео на фоне. Без параметров открывается первая услуга из Redis-ленты сессии, с `id` — услуга по ID, с `id` и `next=true` — следующая. Снизу название и краткое описание с кнопкой «больше / меньше», справа количество лайков, кнопка «Дальше» и два поля по теме. В левом верхнем углу показывается позиция в ленте, например `1 / 100`. Авторизованный пользователь может поставить или снять лайк; гостя кнопка ведёт на страницу входа.

### Плитка — `/grid?min_time={min}&max_time={max}`

Список опубликованных услуг: 2 колонки на телефоне, 3 от `700px`, 4 от `1000px`. Фильтр по времени на 1 Гб хранится в Redux и передаётся в запрос `GET /api/methods`; после поиска значения сохраняются в адресной строке. В карточке изображение, название, количество лайков и время на 1 Гб. Авторизованному создателю показывается кнопка удаления собственной услуги. По клику на карточку открывается лента с этой услуги.

Список постраничный: в запрос передаются `page` и `limit` (10 услуг на страницу), в ответ приходят `total`, `page`, `limit`. Страница хранится в URL `?page=`, при смене фильтра сбрасывается на первую. Компонент `src/components/Pagination/Pagination.tsx` показывает компактный диапазон страниц, а не все страницы при большом `total`.

### Добавление — `/add`

Доступна только авторизованному пользователю, гостя перенаправляет на `/login`. Если у пользователя есть черновик, страница показывает его медиа и форму публикации: описание, время на 1 Гб, коэффициент надёжности. Если черновика нет — форму создания: название, изображение и видео. После публикации происходит переход в ленту на новую услугу.

### Вход — `/login`

Форма входа. Запрос идёт напрямую через axios. После успешного входа состояние пользователя записывается в Redux, в меню появляется «Выход».

## Mock-данные

Если бэкенд недоступен и пользователь находится в состоянии гостя, список услуг и лента берутся из mock-коллекции `src/modules/mock.ts`. В статической сборке GitHub Pages (`VITE_STATIC_MODE=true`) mock используется сразу, без запроса к API. Авторизация и изменяющие запросы без бэкенда не работают.

Mock-плитка тоже постраничная: фильтр применяется к mock-коллекции, затем отдаются 10 записей выбранной страницы.

Если у услуги пустое поле изображения или видео, показываются `public/images/default.svg` и `public/videos/default.mp4`. Медиафайлы MinIO загружаются через прокси `/s3`.
